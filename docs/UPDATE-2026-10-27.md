# Optimizer update — 27 October 2026

**Superseded Windows status:** the 28 October native build succeeds and all 63 native tests pass. See **PORTABLE-UPDATE-2026-10-28.md**. The compiler-block statements below record the earlier state.

Follow-up on 28 October: transfer safeguards now parse complete protocol replies, check stable TV identity around writes, clean their own temporary files, and report confirmed partial counts without automatic retries. The GUI refreshes the photo list after a failure and clears the selected batch to prevent duplicate transfers. Uploads use one full compatibility scan and smaller identity checks between photos. Enabling wallpaper requires photo permission; turning it off remains available. PC wallpaper management currently supports the primary Android TV user (user 0) only, with explicit user targeting.

The wallpaper status and folder-inspection commands were checked read-only on one Android TV. These checks do not substitute for compiling and testing the native Windows integration.

## Interface and apply flow

The overview separates supported changes still available from **Optimizations found**. Existing optimizations are no longer offered as new recommendations.

Individual actions open a shared review dialog, run a read-only preflight, and expose a clear final **Apply** button. Closing a downloaded app uses **Review & close → Close app now**. Canceling the dialog executes no changes. Uninstall retains its additional impact warning. Results distinguish verified success, failure, partial completion and uncertain state; an error is no longer presented as a successful optimization.

Earlier history databases contained no applied change records. The prior controls queued choices into the basket without making the review/apply step obvious. The updated flow addresses that interface cause. Native Close once also reads Android's per-user stopped state after force-stop and reports when Android cannot confirm the close. Apps can restart themselves later; no RAM gain is promised.
